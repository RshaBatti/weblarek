# Интернет-магазин «Web-Larёk»
«Web-Larёk» — это интернет-магазин с товарами для веб-разработчиков, где пользователи могут просматривать товары, добавлять их в корзину и оформлять заказы. Сайт предоставляет удобный интерфейс с модальными окнами для просмотра деталей товаров, управления корзиной и выбора способа оплаты, обеспечивая полный цикл покупки с отправкой заказов на сервер.

## Архитектура приложения

Код приложения разделен на слои согласно парадигме MVP (Model-View-Presenter), которая обеспечивает четкое разделение ответственности между классами слоев Model и View. Каждый слой несет свой смысл и ответственность:

Model - слой данных, отвечает за хранение и изменение данных.  
View - слой представления, отвечает за отображение данных на странице.  
Presenter - презентер содержит основную логику приложения и  отвечает за связь представления и данных.

Взаимодействие между классами обеспечивается использованием событийно-ориентированного подхода. Модели и Представления генерируют события при изменении данных или взаимодействии пользователя с приложением, а Презентер обрабатывает эти события используя методы как Моделей, так и Представлений.

### Базовый код

#### Класс Component
Является базовым классом для всех компонентов интерфейса.
Класс является дженериком и принимает в переменной `T` тип данных, которые могут быть переданы в метод `render` для отображения.

Конструктор:  
`constructor(container: HTMLElement)` - принимает ссылку на DOM элемент за отображение, которого он отвечает.

Поля класса:  
`container: HTMLElement` - поле для хранения корневого DOM элемента компонента.

Методы класса:  
`render(data?: Partial<T>): HTMLElement` - Главный метод класса. Он принимает данные, которые необходимо отобразить в интерфейсе, записывает эти данные в поля класса и возвращает ссылку на DOM-элемент. Предполагается, что в классах, которые будут наследоваться от `Component` будут реализованы сеттеры для полей с данными, которые будут вызываться в момент вызова `render` и записывать данные в необходимые DOM элементы.  
`setImage(element: HTMLImageElement, src: string, alt?: string): void` - утилитарный метод для модификации DOM-элементов `<img>`


#### Класс Api
Содержит в себе базовую логику отправки запросов.

Конструктор:  
`constructor(baseUrl: string, options: RequestInit = {})` - В конструктор передается базовый адрес сервера и опциональный объект с заголовками запросов.

Поля класса:  
`baseUrl: string` - базовый адрес сервера  
`options: RequestInit` - объект с заголовками, которые будут использованы для запросов.

Методы:  
`get(uri: string): Promise<object>` - выполняет GET запрос на переданный в параметрах ендпоинт и возвращает промис с объектом, которым ответил сервер  
`post(uri: string, data: object, method: ApiPostMethods = 'POST'): Promise<object>` - принимает объект с данными, которые будут переданы в JSON в теле запроса, и отправляет эти данные на ендпоинт переданный как параметр при вызове метода. По умолчанию выполняется `POST` запрос, но метод запроса может быть переопределен заданием третьего параметра при вызове.  
`handleResponse(response: Response): Promise<object>` - защищенный метод проверяющий ответ сервера на корректность и возвращающий объект с данными полученный от сервера или отклоненный промис, в случае некорректных данных.

#### Класс EventEmitter
Брокер событий реализует паттерн "Наблюдатель", позволяющий отправлять события и подписываться на события, происходящие в системе. Класс используется для связи слоя данных и представления.

Конструктор класса не принимает параметров.

Поля класса:  
`_events: Map<string | RegExp, Set<Function>>)` -  хранит коллекцию подписок на события. Ключи коллекции - названия событий или регулярное выражение, значения - коллекция функций обработчиков, которые будут вызваны при срабатывании события.

Методы класса:  
`on<T extends object>(event: EventName, callback: (data: T) => void): void` - подписка на событие, принимает название события и функцию обработчик.  
`emit<T extends object>(event: string, data?: T): void` - инициализация события. При вызове события в метод передается название события и объект с данными, который будет использован как аргумент для вызова обработчика.  
`trigger<T extends object>(event: string, context?: Partial<T>): (data: T) => void` - возвращает функцию, при вызове которой инициализируется требуемое в параметрах событие с передачей в него данных из второго параметра.

## Данные

### Интерфейс товара (IProduct)
Описывает структуру данных для товара в каталоге магазина. Используется для отображения товаров, работы с корзиной и передачи данных в API.
interface IProduct {
  id: string;
  description: string;
  image: string;
  title: string;
  category: string;
  price: number | null;
}

### Интерфейс покупателя (UserProfile)
Описывает данные покупателя, необходимые для оформления заказа. Используется при валидации данных, передаче информации в API и отображении в интерфейсе.
interface UserProfile {
  payment: TPayment;
  email: string;
  phone: string;
  address: string;
}

## Модели данных

#### Класс TotalItems
Класс относится к слою Model (данные) и предназначен для управления каталогом товаров, доступных в магазине, а также для отслеживания товара, выбранного пользователем для детального просмотра.

Конструктор класса не принимает параметров.

Поля класса:  
`private items: IProduct[]` - массив объектов типа IProduct. Содержит полный список товаров, загруженных с сервера.
`private preview: IProduct | null` - хранит объект товара, который в данный момент открыт в модальном окне. Если окно закрыто, значение — null.

Методы класса:  
`setItems(items: IProduct[]): void` - записывает полученный массив товаров в поле items. Используется при первичной загрузке данных из API.
`getItems(): IProduct[] `- возвращает актуальный массив всех товаров, хранящихся в модели.
`getProductById(id: string): IProduct | null` — ищет товар в массиве items по указанному id. Возвращает объект товара типа IProduct, если найден, или null, если товар не существует.
`setPreview(item: IProduct | null): void` — устанавливает объект товара в поле preview. Это инициирует событие открытия модального окна в интерфейсе.
`getPreview(): IProduct | null` — возвращает текущий объект товара из поля preview. Если превью не задано, возвращает null.
#### Класс BasketItems
Класс отвечает за хранение выбранных пользователем товаров и управление логикой их покупки. Позволяет динамически изменять состав корзины и вычислять финансовые показатели заказа.  

Конструктор класса не принимает параметров.

Поля класса
`private items: IProduct[]` — массив объектов типа IProduct. Хранит перечень всех товаров, которые пользователь добавил в корзину.  

Методы класса
`add(product: IProduct): void` - принимает объект товара и добавляет его в конец массива items. После добавления инициирует событие обновления состояния корзины.
`remove(id: string): void ` - ищет товар в массиве по его идентификатору (id) и удаляет его. Если в корзине несколько одинаковых товаров, удаляется только один экземпляр.
`getCount(): number ` - возвращает текущую длину массива items (общее количество единиц товара в корзине).
`clear(): void` — очищает массив items, удаляя все товары из корзины. Используется после успешного оформления заказа или по запросу пользователя.
`getItems(): IProduct[]` - возвращает актуальный массив всех товаров, находящихся в корзине, для их последующего рендеринга в интерфейсе.
`getTotalPrice(): number` - рассчитывает суммарную стоимость всех товаров в массиве items. Если цена товара не указана (null), она считается равной 0.
`isInBasket(id: string): boolean` - проверяет, содержится ли в массиве items товар с указанным id. Возвращает true, если товар найден, и false в противном случае (используется для изменения состояния кнопок в каталоге).  

#### Класс IBuyer
Класс относится к слою Model. Он отвечает за хранение контактных данных покупателя, адреса доставки и выбранного способа оплаты, а также за проверку корректности этих данных перед отправкой заказа.  

Конструктор класса не принимает параметров.

Поля класса
`private payment: TPayment`— выбранный способ оплаты.
`private email: string` — контактный e-mail пользователя.
`private phone: string` — контактный номер телефона.
`private address: string `— адрес доставки товара.

Методы класса
`setData(data: Partial<UserProfile>): void` — записывает значения в соответствующие поля класса (например, при вводе данных в форму). Принимает объект с одним или несколькими полями из интерфейса UserProfile.
`getData(): UserProfile` — возвращает объект, содержащий все текущие данные покупателя для последующей передачи в API при оформлении заказа. Возвращаемый объект соответствует интерфейсу UserProfile.
`validate(): UserProfileValidationErrors`— выполняет валидацию всех полей модели по следующим правилам:
- payment не должен быть null;
- email не должен быть пустой строкой;
- phone не должен быть пустой строкой;
- address не должен быть пустой строкой.
Возвращает объект с ошибками валидации типа UserProfileValidationErrors. Если все поля валидны, возвращается пустой объект {}.
`clearData(): void` — сбрасывает все поля в исходное состояние (null или пустая строка) после успешного завершения заказа.

### Слой коммуникации

#### Класс CommunicationApi
Отвечает за взаимодействие с сервером «вебларёк»: получение данных (каталог товаров) и отправку данных (информация о заказе).
Конструктор:
`constructor(api: IApi)` - конструктор инициализирует экземпляр CommunicationApi, сохраняя переданный объект api в приватном свойстве. Это позволяет классу выполнять HTTPзапросы через указанный APIклиент.

Поля класса:  
`private api: IApi` — экземпляр класса Api, предоставляющий методы get и post

Методы класса
`fetchProducts(): Promise<FetchData>` -  выполняет GET‑запрос на эндпоинт /product/ для получения каталога товаров с сервера.
Возвращаемое значение: Promise<FetchData> — промис, который при успешном выполнении разрешается объектом типа FetchData.
Логика работы:
вызывает метод api.get('/product/');
преобразует ответ сервера в объект типа FetchData;
при ошибке: логирует сообщение в консоль через console.error();
пробрасывает ошибку дальше с помощью throw.
Исключения: выбрасывает ошибку при сетевом сбое или некорректном ответе сервера.
`sendOrder(orderData: IOrder): Promise<OrderResponse>` - выполняет POST‑запрос на эндпоинт /order/ для отправки данных о заказе на сервер.
Параметры:
`orderData (IOrder)` — объект с данными заказа, содержащий:
payment, email, phone, address — данные покупателя (наследуются от UserProfile);
total — общая стоимость заказа;
items — массив идентификаторов товаров (string[]).
Возвращаемое значение: Promise<OrderResponse> — промис, который при успешном выполнении разрешается объектом типа OrderResponse.
Логика работы:
вызывает метод api.post('/order/', orderData);
преобразует поле data из ответа сервера в объект типа OrderResponse;
при ошибке: логирует сообщение в консоль через console.error();
пробрасывает ошибку дальше с помощью throw.
Исключения: выбрасывает ошибку при сетевом сбое, некорректных входных данных или ошибке на стороне сервера.


### Слой представления (View)

#### Класс Header
Представление шапки сайта, отображает логотип, корзину с счетчиком товаров и обработчик клика по кнопке корзины.

Конструктор
`constructor(container: HTMLElement, events: IEvents)`
- container: Корневой элемент разметки заголовка.
- events: Брокер событий для передачи действий пользователя (клик по корзине) в презентер.

Поля 
`protected counterElement: HTMLElement` — элемент для отображения количества товаров.
`protected basketButton: HTMLButtonElement `— кнопка открытия корзины.

Свойства (Setters)
`set counter(value: number)` — отображает текст счетчика корзины.

События
Класс инициирует следующие события через брокер:
`basket:open `— вызывается при нажатии на кнопку _basket.

#### Класс Gallery
Представление списка карточек товаров.

Конструктор
`constructor(container: HTMLElement)`
- container: Корневой элемент разметки.

Поля 
`protected catalogElement: HTMLElement `— контейнер, куда будут рендериться карточки товаров.

Свойства (Setters)
`set catalog(items: HTMLElement[]) `— заменяет содержимое контейнера списком переданных элементов (отрисованных карточек).

#### Класс Modal
Представление модального окна.

Конструктор
`constructor(container: HTMLElement, events: IEvents)`
- container: Элемент #modal-container.
- events: Брокер событий для уведомления системы о закрытии окна.

Поля 
`protected closeButton: HTMLButtonElement` — кнопка закрытия.
`protected content: HTMLElement` — контейнер для динамического контента.

Методы класса
`open(content: HTMLElement)`— отображает модальное окно. Генерирует событие modal:open.
`close(): void `— скрывает окно, очищает контент. Генерирует событие modal:close.

Свойства (Setters)
`set content(value: HTMLElement | null)` — заменяет текущее содержимое на новый элемент.

#### Класс OrderSuccess
Представление содержимого модального окна после успешной оплаты заказа.

Поля класса (Элементы разметки):
`protected closeButton: HTMLButtonElement`— кнопка закрытия корзины.
`protected descriptionElement: HTMLElement` — элемент для отображения суммы списанных средств.

Методы:
`set total(value: number)` — сеттер для обновления текста о списанных синапсах. Подставляет значение в строку: «Списано value синапсов».

События:
При клике по кнопке закрытия генерируется событие success:close для уведомления внешнего контроллера.

`constructor(container: HTMLElement, events: IEvents)`

#### Класс CardPreview

Поля класса:
`protected imageElement: HTMLImageElement` — элемент изображения.
`protected categoryElement: HTMLElement` — элемент категории.
`protected textElement: HTMLElement `— элемент с описанием товара.
`protected buttonElement: HTMLButtonElement` — кнопка добавления в корзину.

- `titleElement`

#### Класс Basket
Представление корзины товаров (шаблон #basket), отвечающее за вывод списка выбранных карточек, управление итоговой стоимостью и переход к оформлению.

Поля класса:
`protected listElement: HTMLElement` — контейнер для списка товаров.
`protected totalElement: HTMLElement` — элемент для отображения общей стоимости.
`protected submitButton: HTMLButtonElement`— кнопка перехода к оформлению заказа.

Сеттеры:
`set items(value: HTMLElement[])` — заполняет список товаров в корзине. Если корзина пуста, отображает соответствующее уведомление.
`set total(value: number)` — устанавливает значение итоговой стоимости в «синапсах».
`set enabled(value: boolean)` — управляет состоянием активности кнопки «Оформить» (делает её активной или блокирует).

События:
При клике на кнопку _button генерирует событие basket:order.

#### Класс Form
Абстрактный класс для работы с формами, предоставляющий общие методы управления состоянием полей и валидацией.

Поля класса:
`protected formElement: HTMLFormElement` - форма.
`protected submitButton: HTMLButtonElement` — кнопка отправки формы.
`protected errorsElement: HTMLElement` — элемент для отображения сообщений об ошибках.

Сеттеры:
`set valid(value: boolean)` — управляет доступностью кнопки отправки (активирует или блокирует).
`set errors(value: string)` — устанавливает текст ошибки в соответствующий элемент.

События:
submit — генерируется при отправке формы.input — генерируется при изменении значений в полях ввода формы.

#### Класс Order
Представление формы выбора способа оплаты и ввода адреса доставки (шаблон #order). Расширяет класс Form.

Поля класса:
`protected buttonCard: HTMLButtonElement` — кнопка выбора способа оплаты «Онлайн» (button[name="card"]).
`protected buttonCash: HTMLButtonElement` — кнопка выбора способа оплаты «При получении» (button[name="cash"]).
`protected addressInput: HTMLInputElement` — поле ввода адреса доставки (input[name="address"]).

Сеттеры:
`set address(value: string)` — устанавливает значение в поле ввода адреса.
`set payment(TPayment | null) `— подсвечивает активную кнопку выбора способа оплаты.

События:
При клике на кнопки выбора оплаты генерирует событие `order:payment-change`.
При изменении адреса генерирует событие `order.address:change`.


#### Класс Contacts
Представление формы с контактными данными пользователя (шаблон #contacts). Расширяет класс Form.

Поля класса:
`protected emailInput: HTMLInputElement` — поле ввода почты (input[name="email"]).
`protected phoneInput: HTMLInputElement` — поле ввода номера телефона (input[name="phone"]).

Сеттеры:
`set email(value: string) `— устанавливает значение в поле ввода Email.
`set phone(value: string)` — устанавливает значение в поле ввода телефона.

События:
При изменении полей ввода генерирует события contacts.email:change и contacts.phone:change соответственно.

### События 

#### Глобальные события интерфейса (через брокер событий).
Эти события инициируются классами представления для уведомления системы о действиях пользователя:
 
`basket:open` (Класс Header) — генерируется при клике на кнопку корзины в шапке сайта. Служит сигналом для открытия модального окна корзины.
`modal:open `(Класс Modal) — генерируется в момент отображения модального окна на экране.
`modal:close` (Класс Modal) — генерируется при скрытии модального окна (клик по кнопке закрытия, оверлею или программный вызов).
`card:toBasket` (Класс CardPreview) — генерируется при клике на кнопку действия в окне предпросмотра товара (добавление товара в корзину).
`basket:order `(Класс Basket) — генерируется при клике на кнопку «Оформить» в корзине. Переводит пользователя к первому шагу оформления заказа.
`order:payment-change `(Класс Order) — генерируется при выборе способа оплаты (кнопки «Онлайн» или «При получении»). Передает информацию о выбранном способе.
`order:submit `(Класс Order) — генерируется при нажатии кнопки подтверждения в форме адреса и оплаты.`contacts:submit `(Класс Contacts) — генерируется при нажатии кнопки подтверждения в форме контактных данных. Инициирует завершение оформления заказа.
`success:close `(Класс OrderSuccess) — генерируется при клике на кнопку закрытия в окне успешной оплаты.
 
#### Обработчики действий (Callbacks в конструкторе).
Некоторые компоненты используют функции-обработчики, передаваемые через объект actions при создании экземпляра класса:

`onClick` (Класс CardCatalog) — вызывается при клике на карточку товара в галерее. Используется презентером для открытия модального окна с превью этого товара.
`onClick` (Класс CardBasket) — вызывается при нажатии на кнопку удаления товара из списка корзины. Используется для удаления товара из модели данных.
`onClick` (Класс CardPreview) — вызывается как дополнительное действие при клике на кнопку покупки/удаления в превью товара.

#### События изменений в моделях данных.
Генерируются моделями при изменении внутреннего состояния данных:
`basket:changed (Модель BasketItems)` — генерируется при любом изменении состава корзины (добавление, удаление, очистка). Передает актуальный список товаров, их количество и общую стоимость.
`buyer:changed (Модель IBuyer)` — генерируется при изменении данных покупателя (адрес, оплата, почта, телефон) или их очистке. Служит сигналом для обновления валидации в формах.

#### События отправки форм (Submit).
Наследуются от абстрактного класса Form и инициируются через метод onSubmit:

`order:submit` — подтверждение первой части данных заказа.
`contacts:submit` — окончательное подтверждение данных и совершение покупки.

### Presenter (main.ts)

Презентер является центральным узлом управления приложением. Он инициализирует все необходимые сущности и определяет правила их взаимодействия через подписки на события брокера IEvents.

#### Основные функции и переменные (поля логики):
- Инициализация: 
В начале файла создаются экземпляры API (CommunicationApi), брокера событий (EventEmitter), моделей данных (TotalItems, BasketItems, IBuyer) и корневых компонентов представления (Header, Gallery, Modal).
- `currentModalContent`: Переменная, хранящая текущий DOM-элемент, предназначенный для отображения в модальном окне.
- `formsState`: Объект для отслеживания состояния валидности форм (Order и Contacts).

#### Методы и обработчики (Логика взаимодействия):
`init()` и `loadData()`
Выполняется запрос к API для получения списка товаров.
Полученные данные передаются в модель TotalItems через метод setItems.
После срабатывания события items:changed, презентер создает карточки CardCatalog и наполняет ими галерею.

`handleBuyerChange(data)`
При получении данных из форм (через события изменения полей), презентер вызывает IBuyer.setData(data).
Слушает событие buyer:validation, генерирует сообщение об ошибке через вспомогательную логику и передает его обратно в активную форму вместе со статусом valid.

`handleFormSubmit(step)`
При получении события order:submit закрывает текущую форму и открывает модальное окно с компонентом Contacts.
При получении события contacts:submit инициирует процесс отправки заказа.

`sendOrder()`
Собирает данные из модели корзины (список ID товаров) и модели покупателя.Формирует итоговый объект заказа и отправляет его через метод API post.
При успешном ответе вызывает метод clearData() и открывает компонент OrderSuccess.

`clearData()`
Вызывает методы clear() в модели корзины и clearData() в модели покупателя.
Обнуляет состояние форм и визуальный счетчик товаров в хедере.
`updateModal(view)`
Универсальная логика: принимает любой компонент представления (Basket, Order, CardPreview), вызывает его метод render() и передает результат в Modal.open().

#### Список обрабатываемых событий (this.events.on):
Презентер подписывается на все события, объявленные в слоях View и Model:
От моделей: `items:changed, preview:changed, basket:changed, buyer:validation.`
От представлений: `basket:open, card:toBasket, basket:order, order:submit, contacts:submit, success:close.`
